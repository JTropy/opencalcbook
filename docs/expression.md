# 表达式语法参考

OpenCalcBook 的表达式引擎（`src/expr.js`）是一个 Pratt / 优先级爬升解析器。
它面向工程量计算场景，所以做了两件一般表达式库不会做的事：**行引用是惰性的**
（便于上层做循环检测与缓存），以及**标识符允许中文**（以便用中文命名函数和参数）。

---

## 1. 记号

| 记号 | 写法 | 说明 |
| --- | --- | --- |
| 数字 | `12` `3.14` `.5` `1.5e3` | 十进制，支持科学计数法 |
| 字符串 | `'文本'` `"文本"` | 单引号内 `''` 表示一个字面单引号 |
| 行引用 | `[1]` `[1.2]` `[A-1]` | 方括号内内容原样当编号，可以有 `.` `-` `_` |
| 常量引用 | `@K1` | `@` + 标识符 |
| 变量引用 | `$HNT` | `$` + 标识符 |
| 标识符 | `面积` `a` `_x1` `矩形面积` | 首字符非数字，后续可含数字、下划线、任意 CJK 字符 |
| 关键字 | `true` `false` `null` `nil` `and` `or` `not` `div` `mod` | 大小写不敏感 |

## 2. 运算符与优先级

从低到高（同级左结合，`^` 右结合）：

| 优先级 | 运算符 | 说明 |
| --- | --- | --- |
| 1 | `? :` | 三元条件 |
| 2 | `\|\|` `or` | 逻辑或（短路） |
| 3 | `&&` `and` | 逻辑与（短路） |
| 4 | `=` `==` `<>` `!=` `<` `<=` `>` `>=` | 比较 |
| 5 | `..` | 行区间（两端必须是行引用） |
| 6 | `+` `-` | 加、减；任一侧为字符串时 `+` 表示拼接 |
| 7 | `*` `/` `%` `mod` `div` | 乘、除、取余、整除（向零取整） |
| 8 | `^` | 幂（右结合） |
| 9 | `-` `+` `!` `not` | 一元 |

注意：一元负号优先级**低于**幂，所以 `-2^2` 等于 `-4`；指数位置允许带符号，`2^-3` 合法。

`.` 用于成员访问，只能跟在行引用后面。

## 3. 类型与隐式转换

运行期只有五种值：`number`、`string`、`boolean`、`null`、以及内部的**行引用 / 区间**对象。

- 算术运算遇到字符串会尝试 `parseFloat`（去掉千分位逗号），失败得 `NaN`。
  行结果为 `NaN` 时按**无值**处理（显示为空），不会静默变成 0。
- `+` 只要有一侧是字符串就做拼接，不做数值相加。
- 比较：两侧都是数字按数值比；两侧都是字符串按字典序比；一侧是字符串一侧是数字时，
  **只有字符串能严格解析为数字**才按数值比较，否则 `=` 为假（因此 `'' = 0` 是假）。
- `and` / `or` / `not` 与 `iif()` 用同一套真值规则：`''`、`'0'`、`'false'`、`'no'`、`'否'`、
  `0`、`NaN`、`null` 为假，其余为真。

## 4. 行引用与字段

```js
[1.2]              // 计算结果
[1.2].gcl          // 工程量
[1.2].name         // 项目名称
[1.2].part         // 部位
[1.2].unit         // 单位
[1.2].factor       // 系数
[1.2].value        // 计算结果（同 [1.2]）
[1.2].remark       // 备注
[1.2].code         // 引用代码
[1.2].depth        // 树深度
[1.2].自定义字段名  // 用户自定义列
```

区间：

```js
sum([1]..[5])      // 第 1 行到第 5 行（按显示顺序）的结果之和
avg([1]..[5])
count([1]..[5])    // 非空计数
max([1]..[5])
```

## 6. 错误处理

引擎抛 `ExprError`（带 `pos` 字符偏移）。常见的错误信息：

```
未定义的常量 @XXX
未定义的变量 $XXX
未定义的函数 "XXX"
找不到编号为「1.2」的行
区间 ".." 的两端必须是行引用，例如 [1]..[5]
除数为零
函数 "round" 需要 1~2 个参数，实际收到 3 个
检测到循环引用：编号「[1.2]」间接引用了自己
```

界面上语法错误会即时标红，并把行号和原因列在「问题」里，点一下即可定位。

## 7. 在代码里使用

```js
const CBExpr = require('./src/expr.js');

CBExpr.run('1 + 2 * 3');                       // 7
CBExpr.check('1 + * 2');                       // { ok:false, message:'…', pos:4 }
CBExpr.deps('[1] + @K + $V + 圆形面积(1)');
// { rows:['1'], constants:['K'], variables:['V'], functions:['圆形面积'] }
```

`run(源码, 上下文)` 的上下文需要实现这些方法（详见 `src/model.js` 的 `makeContext`）：

```js
{
  const(name), variable(name), row(编号),
  deref(行引用, 字段名), rowRange(起, 止),
  customFunction(name), invokeCustom(函数对象, 实参表, 语法节点),
  builtin            // 可选，覆盖内置函数表
}
```

内置函数表可以通过 `CBExpr.builtins` 读改；单位换算通过
`CBExpr.setUnitConverter(fn)` 注入（`units.js` 加载时会自动接线）。
